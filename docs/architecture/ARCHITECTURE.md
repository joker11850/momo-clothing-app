# معماری

## ماژول‌ها
`shared-core` یک کتابخانه‌ی Kotlin/JVM خالص است (بدون Android و بدون java.time تا روی API 23 امن باشد).
هر دو اپ به آن وابسته‌اند. بعداً لایه‌ی Repository (محلی ← سرور) روی همین مدل‌ها ساخته می‌شود.

## قواعد ثابت
- همه‌ی مبالغ `Long` به تومان هستند، هرگز Double.
- درصد تخفیف با رُند به بالای نیم‌واحد محاسبه می‌شود.

## قیمت‌گذاری (`PricingEngine`)
1. قیمت اختصاصی مشتری (نهایی است و تخفیف روی آن اعمال نمی‌شود)
2. قیمت عمده (فقط مشتری عمده‌ی تأییدشده و غیرمسدود؛ اگر قیمت عمده خالی باشد، خرده)
3. قیمت خرده
سپس بهترین تخفیف قابل اعمال (بدون جمع‌شدن تخفیف‌ها). کد هدیه فقط با واردکردن کد فعال می‌شود.

## موجودی (`InventoryLedger`)
موجودی قابل فروش = موجودی فیزیکی − رزرو. رزرو سفارش خرده و عمده جداگانه ثبت می‌شود و مدت هرکدام قابل تنظیم است.
رزرو کل سفارش یا انجام می‌شود یا هیچ. کسر واقعی موجودی هنگام ارسال (یا تحویل حضوری) انجام می‌شود؛ مرجوعی کالا را برمی‌گرداند.

## سفارش (`OrderStateMachine`, `OrderProcessor`)
- خرده: جدید ← در انتظار پرداخت ← پرداخت‌شده ← آماده‌سازی ← ارسال ← تحویل
- عمده: جدید ← در انتظار تأیید فروشنده ← (در انتظار پرداخت | آماده‌سازی برای خرید دفتری)
- لغو تا قبل از ارسال، مرجوعی بعد از ارسال. سفارش پرداخت‌نشده با پایان مهلت رزرو لغو می‌شود.

## حسابداری
- `PartyLedger`: دفتر حساب هر مشتری یا تأمین‌کننده؛ مانده‌ی مثبت یعنی بدهی طرف مقابل به ما (مشتری) یا بدهی ما (تأمین‌کننده).
- چک فقط هنگام «وصول» روی حساب اثر می‌گذارد؛ چک برگشتی بعد از وصول معکوس می‌شود. چک‌های باز در مانده لحاظ نمی‌شوند (محافظه‌کارانه).
- `CreditService`: سیاست خرید دفتری (ممنوع / تا سقف اعتبار / با تأیید مدیر).
- `ReportEngine`: سود ناخالص خرده و عمده، هزینه‌ها و سود خالص؛ هزینه‌ی شخصی جدا گزارش می‌شود.

## هنوز انجام نشده
ذخیره‌سازی محلی، رابط کاربری، گزارش‌های کامل، فاکتور تصویری، اعلان‌ها، امنیت (Keystore/PIN)، اتصال به سرور.
